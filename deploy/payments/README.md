# 订单与支付接入边界

注册站已经提供 `RegistryBillingProvider` 服务边界，以及仅限组织所有者访问的方案查询和托管结账接口。默认没有装载任何 provider，因此运行状态显示“未配置”，结账接口返回未配置；仓库不保存商户密钥，也不会产生真实交易。

## 正式适配器必须实现

1. 方案由服务端白名单映射到 Stripe Price 或支付宝商品，不接受浏览器提交金额、币种、手续费或商户账号。
2. 同一个 `organizationId + idempotencyKey` 只能创建一个结账意图。Stripe 使用 Checkout Sessions；订阅使用 Billing + Checkout，不自行循环调用 PaymentIntent。
3. 返回第三方托管的 HTTPS 结账地址。浏览器支付成功跳转只用于展示，不能把订单标记为已支付。
4. 订单状态只由验签通过且防重放的 Webhook 更新；保存 provider event id、订单状态机和审计时间，不保存卡号、支付密码或支付宝私钥明文。
5. Webhook 先持久化再应答，并允许安全重试。退款、争议、订阅取消和失败续费必须进入显式状态。
6. Stripe 与支付宝是两个独立 adapter，任何一个都不能从另一个的回调推断成功。平台手续费必须使用商户后台或服务端固定配置，不能信任客户端比例。

## 仍需部署者提供

- Stripe 商户、产品/Price、Webhook endpoint secret；若要代收分账，需另行完成 Connect 平台合规与账户设计。
- 支付宝开放平台应用、应用私钥、安全保存的支付宝公钥/证书、回调域名和签约产品。
- 价格、税费、退款、隐私、用户协议与发票规则。
- 公网 HTTPS 域名和独立秘密管理。不要把 `.pem`、API key 或 populated `.env` 提交到仓库。

缺少以上资料时，正确状态就是保持支付关闭；这不会阻止组织、Harness 绑定、披露和 A2A 文本请求 MVP 上线验证。
