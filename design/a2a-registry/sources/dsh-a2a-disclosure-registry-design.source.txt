# DSH A2A 对话披露与注册站设计规格

- 日期：2026-08-22
- 状态：可执行合同已补充；阶段 0 的披露线协议已实现，注册站与产品流程待实现
- 产品范围：DeepSeek Harness（DSH）插件、DSH 注册站、组织权限与 DSH↔DSH A2A

## 1. 摘要

本项目让一台设备上运行的 DeepSeek Harness Agent 实例注册到 DSH 注册站。用户可以在某段 DSH 对话旁点击「披露」，把该对话的完整既有历史以及后续新增消息，持续同步给指定组织、团队或成员。

获得授权的成员可以在注册站查看披露内容，并以两种方式使用它：

1. 把披露上下文交给自己的 DSH，创建独立分支继续工作。
2. 向来源 DSH 发起 A2A 问答，在独立分支中与来源 Agent 沟通。

外部成员不能直接写入原对话，也不会因为可以读取上下文而继承来源 DSH 的文件、工具、账号或执行权限。任何动作请求都需要独立能力和人工批准。

第一版采用中央注册站与事件中继架构。本地 DSH 主动建立出站连接、推送已披露数据并接收结构化 A2A 请求；注册站不能主动扫描本地设备。

## 2. 已确认的产品决策

1. DSH 指一台设备上运行的 DeepSeek Harness Agent 实例。
2. 默认授权为：读取披露上下文并创建 A2A 分支；执行或写入需要额外授权。
3. 披露对象必须由用户指定，可以是组织、团队或成员；不默认开放给全组织。
4. 本地 DSH 主动向注册站推送事件，注册站不能主动拉取本地未披露数据。
5. 外部沟通使用独立 A2A 分支，不写入原始对话消息流。
6. 首次披露同步完整历史，此后持续同步新增消息，直到到期、暂停或撤回。
7. 第一版只支持 DeepSeek Harness，不同时兼容其他 Agent 平台。
8. 第一版采用中央注册站和事件中继，未来保留 P2P、自托管和联邦扩展边界。

## 3. 目标与非目标

### 3.1 产品目标

- 用户可在本地 DSH 中用一次明确操作披露指定对话。
- 被授权者可随时查看已同步上下文，即使来源 DSH 当前离线。
- 被授权者可把上下文交给自己的 DSH，或向来源 DSH 发起问答。
- 对话所有者始终知道披露给谁、同步到哪里、谁访问过以及如何撤回。
- 注册站提供组织结构、DSH 在线目录、披露对话目录、A2A 工作区和审计能力。
- 网络或注册站故障不影响本地 DSH 正常对话。
- 系统对跨组织越权、提示注入、实例冒充和远程工具滥用保持默认拒绝。

### 3.2 第一版非目标

- 远程执行 shell、修改来源设备文件或自动使用来源工具。
- 公开链接、匿名访问或互联网公开对话。
- 多人共同写入原始对话。
- 第三方 Harness 兼容和跨注册站联邦。
- 严格端到端加密。
- 全量正文的全局语义搜索。
- 复杂计费、Agent 市场或交易结算。

## 4. 系统边界与组件

### 4.1 本地 DSH 端

#### DSH Core

保留现有原始对话、模型调用、工具执行和 Agent 生命周期。注册站只能通过插件规定的结构化协议与它交互，不能获得任意代码执行入口。

#### Disclosure Plugin

嵌入 DSH 对话界面，在每段对话旁提供「披露」按钮，负责选择授权对象、有效期、附件策略、允许能力和排除项，并展示同步、访问和撤回状态。

#### Sync Agent

后台出站连接组件，负责实例注册、心跳、历史回填、增量同步、断线补传、A2A 请求接收和响应发送。

#### Local Policy Guard

在数据离开设备之前识别和拦截密钥、令牌、密码、环境变量、私有文件、高风险工具输出和被用户排除的内容。

### 4.2 DSH 注册站

#### Identity & Organization

管理用户、组织、团队、成员、邀请和角色。角色包括 Owner、Admin、Member、Guest。组织身份本身不授予对话读取权。

#### DSH Registry

保存 DSH Agent Card、所属用户与设备、协议版本、能力声明、在线状态和最近心跳。

#### Conversation Disclosure Service

管理披露策略、授权对象、内容范围、有效期、附件策略、暂停和撤回。所有读取与分支创建均重新检查授权。

#### Realtime Gateway

维护 DSH 的出站 WebSocket 连接和浏览器实时订阅，接收心跳、同步事件和 A2A 响应，并向在线 DSH 路由经过鉴权的结构化请求。

#### Event Store

以不可变事件保存已披露对话和 A2A 分支。事件具有会话内序号、幂等键、来源、时间、内容哈希和加密载荷。

#### A2A Broker

验证访问权限，创建独立分支，建立上下文快照，路由请求与响应，维护分支状态。Broker 不把外部消息写入来源原对话。

#### Web Console

提供组织管理、我的 DSH、披露对话、A2A、权限和审计界面。

## 5. 身份与数据模型

身份层级为：

`用户 → 设备 → DSH 实例 → 原始对话 → 披露授权 → A2A 分支`

### 5.1 核心实体

- `User`：注册站用户身份。
- `Organization`：租户和协作边界。
- `Team`：组织内成员分组。
- `Membership`：用户与组织或团队的关系和角色。
- `Device`：已绑定设备，保存设备公钥和撤销状态。
- `DSHInstance`：本地运行实例及其 Agent Card、能力和在线状态。
- `Conversation`：首次披露后创建的原始对话映射。
- `ConversationEvent`：消息、修订、删除、附件和标题变化等不可变事件。
- `Disclosure`：一次披露的策略、内容范围、生命周期和默认能力。
- `DisclosureGrant`：授权给具体用户、团队或组织的能力记录。
- `AccessRequest`：其他用户或 DSH 对某段上下文提出的权限申请，包含申请能力、用途、有效期和审批状态。
- `A2ABranch`：基于披露上下文创建的独立工作分支。
- `BranchEvent`：A2A 分支消息、状态和上下文升级事件。
- `SyncCursor`：客户端和服务端已确认的最大会话序号。
- `AuditEvent`：不含正文的安全审计记录。

未披露对话不在注册站保存标题、摘要或存在性记录。

### 5.2 默认能力

- `conversation.read`
- `branch.create`
- `attachment.download`
- `action.request`

默认只授予 `conversation.read` 和 `branch.create`。附件下载默认关闭；动作申请与动作执行必须分离，动作执行不属于第一版。

### 5.3 权限判定

每次读取、实时订阅或创建分支时依次检查：

1. 用户会话有效。
2. 披露仍处于生效状态。
3. 用户是明确授权对象，或仍属于被授权团队。
4. 请求能力包含在授权中。
5. 事件位于授权的时间和内容范围内。
6. 请求未被风险策略、限流或实例阻止规则拒绝。

前端菜单和按钮隐藏不是安全边界，服务端和数据库访问层必须独立执行相同约束。

### 5.4 权限申请

如果访问者知道某个 DSH 或收到一条上下文邀请，但尚未获得目标对话权限，可以发送访问申请。申请必须说明：

- 申请人和申请人的 DSH
- 希望访问的对话或上下文范围
- 申请 `conversation.read`、`branch.create` 或其他能力
- 使用目的
- 希望的有效期

来源所有者可以批准、缩小范围、修改有效期或拒绝。批准会创建新的 `DisclosureGrant`，而不是让申请本身充当长期令牌。拒绝、过期和撤销均进入审计记录。系统对重复申请限流，并允许所有者关闭陌生人申请。

### 5.5 撤回语义

撤回提交后：

- 本地 DSH 停止上传新增事件。
- 注册站拒绝新的读取、实时订阅和分支创建。
- 未开始处理的 A2A 请求取消。
- 现有分支冻结，不再获得来源更新。
- 最后一项授权撤回后，正文和附件进入延迟删除队列，搜索索引立即删除。
- 审计元数据可继续保留，但不复制正文。

系统应明确告知用户：撤回能够阻止后续系统访问，但不能消除接收者已经阅读、手工复制或合法下载的内容。

## 6. 设备注册与连接

### 6.1 绑定

1. 本地生成设备密钥对，私钥保留在设备安全存储。
2. 插件生成一次性绑定码或二维码。
3. 用户在注册站登录并确认绑定。
4. 注册站记录设备公钥、用户归属和允许作用域。
5. DSH 签署服务端挑战，换取短期令牌。
6. 后续连接同时验证设备签名、令牌和实例状态。

用户可单独撤销设备或 DSH 实例，不影响其他设备。

### 6.2 传输

Sync Agent 建立主动出站的 WSS 长连接。连接只接受版本化结构化消息，包括心跳、同步确认、权限通知、A2A 请求、A2A 响应、暂停和撤回。

注册站不得通过该连接发送任意 shell、代码或文件系统命令。

## 7. 对话披露与同步

### 7.1 首次披露

1. 插件创建披露草稿。
2. 用户选择授权对象、有效期、附件策略、能力和排除项。
3. 注册站创建 `disclosure_id` 和短期上传授权。
4. Local Policy Guard 扫描历史内容。
5. Sync Agent 生成事件清单和内容哈希。
6. 历史事件分批上传并逐批确认。
7. 客户端提交完整历史检查点。
8. 对话切换为实时增量同步。
9. 授权成员收到对话可用通知。

历史回填完成前，对话显示“同步中”，不能创建基于不完整上下文的 A2A 分支。

### 7.2 事件封装

每个事件至少包含：

- 协议版本
- DSH 实例 ID
- 对话与披露 ID
- 事件 ID 和幂等键
- 会话内递增序号
- 事件类型
- 来源时间
- 上一事件哈希和当前内容哈希
- 加密载荷
- 实例签名

### 7.3 Outbox 与补传

本地 Sync Agent 使用持久化 Outbox。事件依次经历：

`待过滤 → 待上传 → 已发送 → 已确认`

只有收到注册站确认后才能从待传队列清除。传输采用“至少一次投递、服务端幂等落库”，实现一次生效。

如果服务端发现会话序号缺口，则暂停提交后续事件并请求补传缺失区间。不同对话之间不要求全局有序。

### 7.4 在线状态

DSH 每 20 至 30 秒发送心跳，上报实例状态、协议版本、A2A 接受能力、当前负载和同步游标。注册站推导：

- `online`
- `busy`
- `paused`
- `degraded`
- `offline`

网页同时展示状态和最后确认时间，避免陈旧绿点造成误解。

## 8. A2A 分支模型

### 8.1 使用此上下文

被授权者选择自己的一个 DSH。注册站把授权范围内的上下文快照交给访问者 DSH，由其继续工作。来源 DSH 离线时仍可使用。

### 8.2 询问此 DSH

请求通过 A2A Broker 路由到来源 DSH，由来源 Agent 在独立分支中回答。来源 DSH 必须在线且允许接收 A2A；否则请求等待或切换为“使用此上下文”。

### 8.3 分支创建

1. 访问者选择模式和目标 DSH。
2. 服务端重新验证披露和能力。
3. 确定允许使用的事件范围。
4. 生成上下文快照、水位序号和内容哈希。
5. 创建 `A2ABranch`。
6. 路由首条请求。
7. 响应写入分支事件流。

原对话与 A2A 分支是两个不同数据对象，通过来源引用关联。

### 8.4 上下文装配

Context Builder 按以下层次装配模型输入：

1. 平台系统与安全规则。
2. 当前用户请求。
3. A2A 协议元数据和授权边界。
4. 来源对话摘要与相关历史片段。
5. 最近消息和必要附件摘要。
6. 当前分支历史。

来源对话属于不可信引用数据。其中的“忽略规则”“执行命令”等内容不能提升为系统指令。

### 8.5 上下文更新

分支默认固定在创建时的上下文水位。来源对话出现新内容时只提示“有新上下文可用”。用户主动点击同步后，系统重新鉴权并记录新的水位和哈希。

### 8.6 分支状态

- `created`
- `waiting_for_agent`
- `active`
- `waiting_for_human`
- `paused`
- `frozen_by_revocation`
- `completed`
- `failed`
- `archived`

### 8.7 工具和动作

读取上下文与创建分支不授予任何本地工具权限。修改文件、运行命令、访问内部服务、发送消息、产生费用或操作外部账户都必须转换为 `action.request`，由来源用户明确批准。第一版只实现请求表达和审计，不实现远程动作执行。

## 9. 插件与网站体验

### 9.1 本地披露按钮

每段对话标题旁显示披露按钮或状态徽标：

- 灰色：未披露
- 蓝色：正在同步
- 绿色：已披露
- 黄色：异常或即将到期
- 红色：暂停或撤回

已披露面板展示授权对象、同步水位、最近同步、读取记录、A2A 分支数量以及修改、暂停和撤回入口。

未获权用户只能看到所有者明确公开的 Agent Card 字段，不能看到未披露对话目录。若所有者允许接收申请，用户可以通过 DSH 卡片或邀请链接发起权限申请；所有者在本地插件或注册站审批后，对话才出现在申请者的披露对话菜单中。

### 9.2 注册站导航

- 概览
- 成员
- DSH
- 披露对话
- A2A
- 权限与审计
- 设置

### 9.3 DSH 目录

DSH 卡片显示实例名称、所有者、设备别名、在线状态、最后心跳、能力和当前用户可访问的披露对话数量。

点击 DSH 后只显示当前用户获准访问的对话，不暴露该实例未披露对话的标题、数量或存在性。

### 9.4 披露对话详情

详情页固定展示所有者、来源 DSH、披露范围、最后同步时间、当前授权能力和上下文状态，并提供：

- 使用此上下文
- 询问此 DSH
- 查看已有分支
- 报告敏感内容

### 9.5 A2A 工作区

A2A 菜单按分支展示来源对话、发起者、处理 DSH、上下文水位、状态、最近响应和是否等待人工批准。

界面体验可以表达为“进入此 Agent 沟通”，但必须持续标明这是独立分支，不是进入对方设备，也不会写入原对话。

## 10. 安全设计

### 10.1 多租户边界

所有组织数据必须携带 `organization_id`，并在 API、数据访问层和数据库行级策略三层执行租户隔离。后台任务、实时推送和搜索索引不得绕过该边界。

组织管理员默认不能读取成员未披露给自己的对话。平台运维人员不通过普通后台界面访问正文。

### 10.2 用户和实例认证

用户登录支持 Passkey、OIDC、MFA、短期会话和高风险操作重新验证。每个设备和实例使用独立密钥；事件和响应由实例签名，并验证实例状态、序号、时间、nonce 和重放风险。

### 10.3 加密

- 传输使用 TLS。
- 每段对话使用独立数据密钥加密正文和附件。
- 数据密钥由平台密钥管理系统封装和轮换。
- 附件使用独立对象密钥和短期签名地址。
- 默认只索引用户允许的标题、标签和摘要。

第一版是平台托管加密，不宣称严格端到端加密。

### 10.4 提示注入和 Confused Deputy

外部披露上下文按不可信数据处理，不能成为系统指令。每个 A2A 请求携带发起用户、发起 DSH、来源披露、授权版本、请求能力、上下文水位和请求 ID。来源 DSH 不能只因为请求来自注册站就信任它，而应再次验证签名、授权和能力。

### 10.5 附件和滥用防护

附件默认不允许下载，优先提供安全预览或文本摘要；限制类型、大小和数量，拦截可执行文件、宏文档和危险压缩包。系统分别限制读取、导出、分支创建、并发任务、附件下载、邀请、失败签名和重放请求。

异常大量读取、跨地域登录、批量创建分支或连续触发敏感检测时，通知所有者并自动收紧访问。

## 11. 故障与降级

- 注册站不可用：本地 DSH 正常工作，Outbox 缓存事件，恢复后补传。
- 来源 DSH 离线：已同步内容仍可读取和用于自己的 DSH；询问来源 DSH 进入等待。
- 网络抖动：指数退避重连，从最后确认游标恢复。
- 历史回填失败：披露保持异常状态，不开放 A2A。
- 撤回与请求竞态：按授权版本和事务提交顺序判定，撤回后的未处理请求取消。
- 权限服务异常：读取、推送、导出和 A2A 全部失败关闭。
- 协议不兼容：实例显示 `degraded`，只保留明确兼容的安全能力。
- 实例疑似被盗：撤销实例密钥、终止连接、冻结其披露并使令牌失效。

## 12. 推荐工程形态

第一版采用模块化单体：

- Web/API 应用：身份、组织、权限、披露、分支和审计。
- Realtime Gateway：DSH 长连接和浏览器订阅。
- Background Worker：历史回填、通知、删除、附件处理和重试。
- PostgreSQL：身份、授权、事件元数据和审计。
- 对象存储：加密附件和大型载荷。

- 密钥管理服务：数据密钥封装与轮换。

同时建立独立、版本化的 DSH A2A 协议包，包含 JSON Schema、事件定义、Agent Card、错误码、签名规则、兼容策略、测试向量和示例客户端。

## 16. V1 冻结范围

### 16.1 包含能力

- 被授权者可在注册站只读查看已完成同步的前缀。

- 来源 DSH 在线时，可在独立 A2A 分支中接收和回复文本问题。

- 附件、图片、文件正文、原始工具输入/输出与隐藏推理。

- 全局全文检索、语义检索、批量导出与跨披露聚合。
- 跨组织共享、公开链接、自托管、P2P、联邦与第三方 Agent 协议。
- 严格端到端加密、客户端可验证删除与离线副本召回。

V1 数据模型保留 `organization_id`、能力字段和协议版本，以免单组织部署把租户边界写死；未实现的能力在 API、UI 和策略中均为拒绝，而不是隐藏入口。

## 17. 披露语义与线协议

### 17.1 语义允许清单

本地 DSH 必须先把内部 `SessionEvent` 投影成披露语义，再执行策略过滤、加密和签名。V1 只允许以下语义事件：

| 类型 | 字段 | 说明 |
|---|---|---|
| `conversation.user-message` | `text` | 用户明确发送的文本 |
| `conversation.assistant-message` | `text` | 最终进入可见对话面的助手文本 |
| `conversation.tool-result-summary` | `toolName`、`outcome`、`text` | 本地策略生成并限制长度的摘要，不得携带原始载荷 |
| `conversation.title` | `title` | 用户可见标题 |

系统提示词、请求 header/context、隐藏推理、工具调用、原始工具结果、审批、凭据、环境变量、工作目录、绝对路径、插件内部事件、运行错误与附件默认排除。Policy Guard 可以继续删除或改写允许清单内的内容，但不能增加新的事件类型。

### 17.2 事件信封

每条加密事件使用 `protocolVersion = 1`，并携带以下精确字段：

- 身份：`organizationId`、`instanceId`、`conversationId`、`disclosureId`、`eventId`。
- 顺序：`disclosureSeq`、`sourceCursor`。
- 语义元数据：`eventType`、`policyVersion`、`occurredAt`。
- 完整性：`previousEventHash`、`ciphertext`、`ciphertextHash`、`eventHash`、`signature`。

`sourceCursor` 表示投影器已检查到本地日志的哪个位置，可以因过滤而跳跃。`disclosureSeq` 只为实际发出的事件编号，从 0 连续递增。注册站用 `eventId` 幂等去重，用 `disclosureSeq` 检测缺口，绝不能把 `sourceCursor` 的跳跃当成丢包。

`ciphertextHash` 对 base64url 解码后的密文字节计算 SHA-256。`eventHash` 对固定字段顺序的 JSON 数组计算 SHA-256，并包含 `ciphertextHash` 与 `previousEventHash`。`signature` 对 `eventHash` 的规范字节签名；算法、密钥 id 与有效期由设备身份握手协商，注册站必须按事件发生时有效的实例公钥校验。

### 17.3 历史检查点

首次同步和每次恢复同步都必须以签名检查点结束。检查点包含 `organizationId`、`instanceId`、`disclosureId`、`policyVersion`、`sourceCursor`、`eventCount`、`lastDisclosureSeq`、`lastEventHash`、`checkpointHash` 与 `signature`。

注册站只有在以下条件全部成立时，才把该历史前缀标记为 `ready`：事件序号从 0 到 `eventCount - 1` 连续；哈希链连续；最后事件哈希与检查点一致；实例签名有效；当前授权仍允许同步。若历史中所有事件都被过滤，则 `eventCount = 0`、`lastDisclosureSeq = -1`、`lastEventHash = null` 仍是有效检查点。

## 18. 首次同步与增量同步算法

### 18.1 建立一致切面

首次披露按以下顺序执行：

1. 本地创建披露记录与持久 outbox，状态进入 `backfilling`。
2. 读取当前会话日志尾部，记录高水位 `H`；随后立即订阅 `H` 之后的新事件，并把它们暂存到同一 outbox。
3. 从来源游标 0 扫描到 `H`，按允许清单与当时的 `policyVersion` 投影。每条发出记录分配连续 `disclosureSeq`，写入 outbox 后才允许发送。
4. 为已检查到 `H` 的前缀生成签名检查点并入队。
5. 按 disclosure 序号发送历史事件、检查点，再发送订阅期间积累的增量；注册站逐条返回最高连续确认序号。
6. 检查点被确认后，本地状态进入 `live`；未确认 outbox 记录不得删除。

“先取快照再订阅”会丢失二者之间的事件，因此不得采用。若会话日志 API 不能原子提供高水位与订阅边界，生产者必须先订阅再取高水位，并按来源事件 id 去重。

### 18.2 重试、冲突与恢复

- outbox 以 `eventId` 为幂等键，至少一次发送；注册站重复接收相同字节时返回原确认。
- 同一个 `eventId` 或 `(disclosureId, disclosureSeq)` 对应不同哈希时，注册站返回不可重试冲突并冻结该披露的摄取。
- 连接恢复时，注册站返回最高连续 `disclosureSeq` 和对应 `eventHash`；本地必须与 outbox 链头核对后续传。
- 任一侧发现哈希不一致、序号倒退或未知协议版本时都进入 `error`，不得跳过记录继续发布。
- 失败重试采用有上限的指数退避与抖动；本地对话线程不等待注册站 I/O。

## 19. 授权合同

所有读取、订阅、导入分支和 A2A 请求都调用同一纯授权判断：

```text
allow(subject, action, disclosure, now) =
  sameOrganization(subject, disclosure)
  AND activeMembership(subject)
  AND disclosure.status == active
  AND now < disclosure.expiresAt
  AND matchingActiveGrant(subject, action)
  AND action IN disclosure.capabilities
```

团队授权在请求时按当前团队成员关系展开，不在授权创建时复制成员列表。每次授权、成员关系、能力范围、到期时间或披露状态变化都递增 `authorizationVersion`。HTTP 响应、WebSocket 订阅和 A2A 排队项记录其评估版本；版本变化时注册站重新求值并关闭不再允许的订阅。列表查询与对象读取使用同一判断，未授权资源统一返回不存在，防止通过标题、计数或错误差异枚举资源。

角色只授予管理组织资源的资格，不隐式授予读取对话正文的权限。Owner/Admin 也必须拥有匹配的披露授权；紧急审计访问若未来实现，必须是独立能力、双人批准和单独审计事件。

## 20. 状态机

### 20.1 披露状态

```text
draft -> backfilling -> live -> paused -> live
                     \-> error -> backfilling
draft/backfilling/live/paused/error -> revoked
revoked -> deleting -> deleted
live/paused/error -> expired
expired -> deleting -> deleted
```

- `draft` 不向注册站发送正文。
- `backfilling` 可摄取但不可向读者发布未完成前缀。
- `live` 接受增量与授权读取。
- `paused` 停止新事件发送并保留 outbox；已同步内容仍按授权可读。
- `error` 停止发布新前缀，保留可诊断状态与未确认 outbox。
- `revoked`、`expired` 立即拒绝新读取、订阅、导入和 A2A 请求。
- `deleting` 执行内容清除；`deleted` 只保留最小合规墓碑与审计摘要。

状态转换使用条件更新并追加审计记录。终态不可通过普通更新恢复；重新披露必须创建新的 `disclosureId` 和新哈希链。

### 20.2 A2A 分支状态

```text
created -> queued -> delivered -> running -> completed
                 \-> expired
                 \-> cancelled
delivered/running -> failed
```

每个状态转换必须幂等。队列项绑定 `disclosureId`、授权版本、上下文检查点和请求者身份；投递前再次授权。来源 DSH 离线只使请求保持 `queued`，不授予注册站执行能力。撤回、到期或成员移除会取消尚未投递的请求；已经生成并返回给请求者的文本按审计记录保留，不声称可远程召回。

## 21. 安全分支与上下文装配

“使用此上下文”和“询问此 DSH”都创建新会话，绝不写入来源会话。导入器不得复制原始 session seed、request header、system prompt、tool registry、credentials、cwd、attachments 或插件内部事件。

导入的新会话使用本地默认 agent 配置，但初始能力固定为无工具、无文件、无 shell、无网络。披露文本作为带来源标识的引用数据进入一个新的持久事件 `a2a/context-imported`；该事件记录 `disclosureId`、检查点哈希、来源显示信息与已导入文本的内容摘要，使模型可见输入可以从本地日志重建。上下文前后必须加入固定边界，明确其中的命令、系统提示词外观和工具调用文本均不具有指令权限。

如未来允许工具，用户必须在目标 DSH 中对新分支单独启用；来源披露能力不能自动传播。A2A 回复只返回文本结果和引用的检查点，不返回来源工具句柄、隐藏提示词或中间执行状态。

## 22. 撤回、删除与威胁模型

### 22.1 撤回与删除语义

- 撤回在授权事务提交后立即阻止新 HTTP 读取、WebSocket 推送、上下文导入和 A2A 投递，并向在线本地实例发送停止同步指令。
- 本地实例收到撤回后停止投影，保留最小发送游标和审计事实，删除尚未获注册站确认的正文 outbox；离线实例重连时先同步授权状态，再允许发送。
- 注册站默认在撤回后进入删除队列；正文、搜索索引、缓存和派生摘要使用同一删除任务追踪。备份按既定保留期到期，不承诺即时物理擦除。
- 已被授权者导入到自己 DSH 的本地副本、已查看内容、人工复制内容和已经返回的 A2A 回复无法召回。UI 和审计必须明确这一限制，不得使用“全局撤销”或“彻底收回”等措辞。
- 审计记录保留资源 id、主体、动作、时间、结果和内容摘要，不保留已删除正文。

### 22.2 主要威胁与控制

| 威胁 | 强制控制 |
|---|---|
| 跨租户 ID 枚举 | 所有查询绑定 `organization_id`；未授权统一为不存在；数据库策略与应用测试双重覆盖 |
| 实例冒充与重放 | 设备绑定、短期连接令牌、事件签名、时间窗、`eventId` 幂等与密钥轮换历史 |
| 提示注入提升权限 | 语义允许清单、引用边界、无工具分支、来源能力不传播 |
| 密钥或私有数据外泄 | 本地 fail-closed Policy Guard、默认排除、用户预览、服务端二次检测 |
| WebSocket 越权存续 | 每条订阅绑定授权版本；版本变化重新求值并主动关闭 |
| 批量抓取与洪泛 | 按用户、组织、实例、披露和 IP 限流；分页上限；异常导出告警 |
| 删除不完整 | 统一删除任务覆盖正文、索引、缓存和派生物；可审计重试与墓碑 |

注册站被攻破时，V1 的服务端可读加密不能保护正在使用的明文；因此“不把高风险内容发送出去”是主要安全边界。严格端到端加密必须作为独立版本设计，不能只替换一个密钥字段。

### 22.3 服务目标

- 在线正常情况下，已确认的新事件 95% 在 5 秒内对授权读者可见。
- 撤回或成员移除提交后，95% 的在线订阅在 5 秒内失效；所有新请求立即按新授权版本判断。
- 进程崩溃或网络中断后，已写入本地 outbox 的记录不丢失；恢复发送可以重复，但不得重复生效。
- 注册站故障不阻塞本地会话追加、模型调用或工具执行。
- 每次摄取冲突、签名失败、越权请求和删除失败都产生可告警的结构化审计事件。
