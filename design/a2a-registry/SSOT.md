# A2A 注册站：产品需求与剩余任务

## 产品需求

### 1. 产品定位

`dsh-a2a-registry` 是可独立部署的多组织 SaaS 注册站。任何通过已配置身份服务完成注册的用户，都可以创建自己的组织、切换本人所属组织、绑定本人的 DeepSeek Harness，并在组织权限范围内管理成员、DSH 节点和披露上下文。

注册站负责账号、组织、成员关系、设备绑定、授权目录、披露索引、导入与纯文本 Agent 请求；Harness 继续负责本地会话、模型与 Agent 执行。注册站不得获得来源 Harness 的 Shell、文件、工具或任意远程执行权限。

### 2. 已实现的 SaaS 基线

- 使用 OIDC Authorization Code + PKCE 登录；身份服务未配置时拒绝受保护访问，不提供假登录。
- 浏览器 Cookie 只保存签名的随机会话 ID 与期限，Access Token 只进入当前单实例进程的有界内存；每个新的受保护 HTTP 请求都向身份服务执行 Token Introspection，停用、过期、主体或客户端不一致时立即删除会话，上游不可用时失败关闭；全局会话满额时拒绝新会话，同一主体超额时确定性淘汰最旧会话。Registry 重启会要求重新登录。
- 未登录用户打开组织内受保护页面时，登录事务只保留经过校验的站内路径，成功后回到原页面，不使用开放重定向或浏览器隐式组织状态。
- 首次登录会创建全局账号；没有组织时进入自助创建组织页面。
- 每个账号最多可创建的组织数由部署配置限制，默认上限为 5。
- 创建组织会在同一事务中写入组织、Owner 成员关系和幂等记录；组织短名全局唯一。
- Owner 可创建 Admin／Member 邀请，Admin 只能创建 Member 邀请；邀请令牌只显示一次，数据库只保存摘要。
- 新用户可以通过邀请链接登录后接受或拒绝加入，Owner／Admin 可以撤销待处理邀请；重复、过期、撤销和跨账号接受均失败关闭。
- 邀请接受后，SaaS 控制面成员关系与组织目录角色绑定；目录中的改角色、暂停、恢复和移除会同步到控制面，移除状态不会被自动复活。
- 当前组织只由 URL 中的 `organizationId` 决定，浏览器 Cookie 或本地存储不保存隐式当前组织。
- 每个组织使用独立 Registry 运行时和独立存储域；HTTP API、设备同步和业务读取都在成员鉴权后再选择组织运行时。
- 新设备绑定使用 v6 记录：Harness 在本机生成 Ed25519 私钥、WSS 设备 secret 和独立 disclosure bridge secret，只提交公钥与两个域分离摘要；Registry 不保存原始 secret。已确认绑定分别生成组织／绑定限定的 `dsh1`、`dshb1`，前者还必须完成 WSS Ed25519 随机挑战签名，后者只用于固定 HTTPS bridge。每次两类鉴权都会从当前所呈 raw secret 同时计算两个域摘要；若另一域摘要命中兄弟凭据，说明客户端复用了 secret，V6 会按未授权失败关闭。旧 v4/v5 记录仍可解析，v5 的 `dsh1` 继续支持 WSS，但不能获得 bridge 权限；旧 V1 工具状态可继续确认或导出五项 connection-only 配置，发布前必须撤销并重新绑定，不能复用旧 secret 伪造 `dshb1`。
- SaaS WSS 会按 token 中的组织选择租户运行时，再以当前绑定、成员状态、scope 和设备公钥鉴权；每次业务操作前重新检查，绑定或成员失效会中止现有连接，重连继续使用同一实例身份。
- Registry 接收端已用真实 v5 设备 WSS 帧跑通披露注册、签名事件、签名检查点、断线重连状态恢复和完全相同帧的幂等重放；重连后可按固定检查点读取同一事件前缀。该证据只覆盖 Registry 接收端，不代替 Harness 侧发布策略和持久离线队列。
- Registry 已按组织建立独立持久导入队列：账号侧只可选择本人当前已确认且具有 `a2a.receive` 的目标，目标离线时可先排队；WSS 按组织与实例精确派发固定检查点，重启后可恢复状态。操作标识只由组织、成员和幂等键确定，请求摘要另行覆盖披露、来源、检查点、授权版本和目标；同键异请求冲突，相同请求重试不重复建项。v1 线协议只传稳定操作标识，目标 Harness 由目标实例与操作标识确定计算本地 Session，并在完成回执中返回；Registry 独立计算并核对该 Session 标识后才完成任务。
- 后台导入派发会在读取和完成写入时分别重查当前成员、披露、固定检查点及目标接收权限；网络等待不占用 Registry 领域存储所有者，并受部署超时限制。交付正文超过独立字节上限，或目标返回的会话标识与预期不符时，该任务会持久标记失败，不阻塞同一目标的后续任务。来源 v5/v6 公钥历史由租户领域内当前绑定重建，不依赖浏览器会话；旧 v4 绑定没有可供后台使用的新鲜外部密钥历史时失败关闭，必须重新绑定。
- Registry 已按组织建立独立持久纯文本提问邮箱：浏览器可提问、分页列出、读取状态与回复、取消仍在排队的请求；来源 DSH 离线时请求保留，Registry 进程重启后继续派发。请求标识只由组织、成员和幂等键确定；完全相同的请求返回原记录，同键更换正文、披露、来源、固定检查点或初始授权版本会明确冲突，不重复执行。
- 提问和回复正文只以每组织派生密钥的 AES-256-GCM 密文保存在租户邮箱域，不进入 Registry 审计、告警或普通日志。每次入队、列表、读取、取消、派发、执行状态变更、授权和回复都会重新确认浏览器账号或 WSS 设备、当前成员与团队、披露授权、固定检查点及来源 v5/v6 绑定。WSS 只按组织和来源实例精确取件，并在发送前独立核对 binding、receipt、prefix 和检查点一致性。
- 提问授权的 WSS 等待不占用披露存储串行锁，并受部署超时限制；断线时未完成请求仍可重投，运行请求按执行租约恢复。完整交付超过独立字节上限时会版本栅栏地标记失败并继续后续请求，不形成队头毒任务。该能力只完成 Registry 半边；Harness review 分支虽已包含本地无工具分支、持久消费回执及回复提交源码，但受保护运行时中的真实模型执行尚未验收。
- SaaS 披露列表、元数据和固定前缀读取会在同一租户存储操作内，从唯一已确认的 v5/v6 绑定重建来源公钥历史；不会信任 OIDC 会话提供设备密钥。重复绑定、成员失效、缺少 `disclosure.sync`、撤销或来源实例不符均按不存在处理；v4 仅保留受绑定约束的外部密钥历史兼容路径。
- SaaS 内建披露操作面只允许独立 `registryDisclosureContentProvider` 投影已经完成读权限校验的固定检查点正文；部署方不能替换导入、提问或授权流程。正式 provider 已把检查点精确作用域与 `registryDisclosureKeyProvider.readDataKeys` 组合：在解包任何数据密钥前限制同作用域历史密钥数量，逐事件核对租户、实例、会话、披露、策略和序号，再以完整 AAD 解密，只投影用户消息、助手消息、工具摘要和标题；任何缺项、篡改、超限或中止均整批失败，不返回部分正文。正文投影前后仍会重新读取并授权同一检查点，最终响应继续受独立字节上限约束；开发图未提供该服务时接口保持 HTTP 501，生产图则固定要求唯一官方 provider、密钥服务注入和显式资源上限。
- Registry 已实现并装配首阶段 `software-local` 披露密钥 provider：只从 environment-only Credentials 读取独立的规范 256 位根密钥，包裹每组织随机 KEK，再按组织、实例、会话、披露和 key id 的完整作用域包裹 Harness 数据密钥；密文 AAD 绑定版本、用途、根密钥标识和全部作用域。provider 按组织惰性打开独立物理域，具有有界并发 opening、引用计数和空闲 LRU，拒绝跨租户、同 key id 异材料、不确定写入和非环境密钥来源；读取会在任何 DEK 解包或 `KeyObject` 创建前执行调用方上限，关闭会停止准入并排空 store。生产图固定要求唯一密钥 provider、唯一正文 provider、显式单实例声明、服务注入、SaaS 开关和 bridge 同时存在；实现仍明确是 software-local、非 HSM、非 attested、非严格端到端、进程内可导出且只支持单写者。
- Registry 已实现固定 `POST /a2a/v1/disclosure-publication` 的生产 bridge，精确支持权限目录、发布容量、租户密钥就绪和幂等数据密钥提供四个操作。每次请求用独立 `dshb1` 重新核对 v6 binding、组织、实例、当前成员和 `disclosure.sync`；请求体／响应／目录／并发均有硬上限，拒绝查询、跨租户 selector、任意深度重复 JSON 成员、非规范密钥和错误回执。未读完正文的拒绝会关闭连接；全链路 deadline 覆盖租户获取、认证、目录和 provider，超时晚到 lease 会释放，尚未结束的非协作依赖继续占用准入名额，关闭本身不被其永久卡住。该容量判断是有界预检，不是持久配额账本。
- 设备自助绑定命令行已提供 `start`、`confirm` 和 `export-env`：私钥与两个原始 secret 只在 Harness 侧生成和保存，组织成员用临时配对码审批后，新绑定导出六项生产变量；Windows 会在任何读取、联网、创建或替换长期凭据前校验固定盘、重解析点和受保护 ACL，状态与导出文件必须作为长期秘密保护。
- 本地 Keycloak 验收栈已在 3181 通过 Registry 就绪探针，并在 3183 通过 Caddy 内部 CA 同时代理 WSS 和 HTTPS publication bridge；本地单实例 Registry 已实际装载受限保存的独立 software-local 根密钥、密钥 provider 与有界正文 provider，无凭据 bridge 探针精确返回 401。新增 v6／bridge／正文链路仍未由组织成员完成真实配对与联合验收；该入口只绑定回环地址，不是公网证书或生产入口。
- 外部 Harness 的 connection-only 模板已接通生产设备鉴权、在线状态和断线重连；完整 publication 模板已接入内建 HTTPS bridge，但真实发布、导入、提问、自动 Session 刷新和模型执行仍须联合验收，任何模板都不开放远程工具执行。
- Registry 与 Harness 的 v1 线协议提供无秘密的双向兼容门禁：目标源码与构建产物必须互相通过设备握手、Presence 心跳、披露注册／事件／检查点、导入派发／释放和纯文本问题派发／运行／完成／失败等代表性帧编解码；目标 web-app 与 session-controller schema 必须分别接受实际 connection-only 和完整 publication overlay，已构建 CLI 还须在彼此隔离的临时 `DSH_HOME` 中完成两层真实配置合成。目标 Session 仍由实例与操作标识确定，Registry 独立计算并校验完成回执；静态完成／失败样本不是一次真实执行轨迹，协议兼容不降低幂等约束，也不证明 KMS 或模型执行可用。
- 当前独立 Harness review 分支已包含生产连接与 Presence、持久披露映射和加密发布队列、冷启动恢复、按目标实例与操作标识创建确定 Session 的导入接收器、手动／自动提问消费、执行租约恢复、回复提交、无工具纯文本执行策略，以及生产披露 HTTPS bridge，共有 10 个提交，最新为 `644681299a`。Bridge 用一个规范 HTTPS 端点提供权限目录、容量检查、密钥就绪和幂等作用域密钥提供；凭据按请求解析，拒绝重定向、重复 JSON 成员、超限正文、错误回执和越过绝对期限的业务解码。A2A 主体在 `3b3b465fff` 的 `build:official` 已成功，最新分支又完成仓库级 tsdown 构建、类型检查、lint 和定向回归；`7eca6cc2b0` 修复了发布安装验证漏装原生 optional prebuild 的问题，实际 packed-install 已从 267 个 tarball 安装并运行 CLI 0.1.2-rc.1。分支尚未推送，按当前比较仍落后上游约 1530 个提交。上述证据不包含真实设备联合端到端验收，当前 3080 也未切换，因此不能视为生产接入证据。
- Windows 受保护 connection-only 运行包准备器已实现：只接受发布 tarball、Node.js 24+ 和尚不存在的版本化目标目录，用 npm 生成实体依赖树，固定禁用生命周期脚本，执行 CLI 与 connection-only 配置烟测，拒绝重解析点，收紧 ACL，记录 lockfile、来源包和逐文件摘要，再原子发布 Node、Harness 与启动器。本地第二版候选已在私有 ACL 命名空间中准备出 Harness 0.1.2-rc.1／Node.js 24.19.0 运行包；最终摘要清单逐项覆盖除清单自身外的 33468 个文件，启动器可在不影响现有 3080 的独立 3180 端口运行。该候选尚未完成真实 v6 审批后的 Web 启动、Registry Presence 和 publication 验收，也不是同步上游后从受保护干净构建账号生成的正式发布物；完整 Agent 原生依赖仍需无秘密构建账号到最终服务账号的两阶段交付，不能在持有设备密钥的账号中执行第三方安装脚本。
- 本轮 Registry 当前工作树全量回归 105 项全部通过，生产构建、三层生产图、Node.js 24 环境门禁、Caddy 配置语法和本地完整运行图启动均通过；bridge、双凭据、software-local KMS 和正式正文 provider 的独立审查问题均已修复并加入定向回归。这证明代码与配置门禁闭合，不代替真实身份、真实设备、真实公网或灾备演练。
- PostgreSQL 业务表和 SaaS 控制面表均包含租户键并启用强制行级安全；每个事务显式设置当前账号或组织上下文。
- 支付提供方中立的持久化订单核心已进入 SaaS 控制面 schema v3：`billing_orders` 保存服务端方案快照、组织级幂等键和订单状态，`billing_provider_events` 以支付提供方事件标识防重放并保留不含支付正文的审计记录；两表均按组织强制行级安全。订单状态按创建、待结账、失败、过期、已付款、争议、已退款的固定优先级单调投影；每个已验签事件先留存，同时间戳、乱序或低优先级事件只能补齐确定性的时间记录，不能使状态倒退或清除争议。
- 支付异步通知已有固定、无需浏览器登录的提供方中立入口：所有该前缀请求先按来源地址限流，再校验方法、查询和提供方，并有界保留原始字节与重复请求头交给部署适配器验签并核对商户与时间；Registry 强制使用路径提供方、自算正文摘要且不保存原文，只有计费事件事务提交后才返回固定成功响应，适配器不能回显请求或秘密。生产配置必须同时出现固定 `registry-billing-provider` 条目、`saas.billingProvider: true` 和 `registryBillingProvider` 生命周期注入，缺一失败关闭；仓库仍没有 Stripe／支付宝真实商户适配器。
- 组织 Owner 已可在设置页查看方案、创建第三方托管结账和查看有界订单列表；浏览器不能提交金额或凭跳转标记付款。未装载 Stripe／支付宝适配器时，界面明确显示支付未配置，相关 API 在 Owner 鉴权后返回 HTTP 501。
- PostgreSQL 由离线 `registry_migrator` 持有 schema／表并执行 DDL，在线 `registry_app` 只有最小业务权限；在线启动只读校验版本、策略和表权限，任何直接或角色链上的 DDL、临时表、超级用户、绕过行级安全、元数据写入或危险表权限都会失败。日常启动不自动执行结构迁移。
- SaaS `/readyz` 会分别通过实际 storage pool 与 tenancy pool 核对 PostgreSQL 权威版本标记，并拒绝非 PostgreSQL 的 domain 路由；数据库不可用、版本缺失或应用尚未完成加载时返回 503，恢复后无需重启即可重新就绪。公开探针使用单飞、HTTP／查询／连接有界等待和短缓存，避免并发健康检查放大数据库连接；`/healthz` 只表示 Registry 进程仍存活。
- 当前本地旧站与 SaaS 共库期间仅本地 patch 有显式不安全过渡开关，允许在线账号继续持有其他 legacy schema；生产禁止启用，P-MIGRATE 完成后必须删除。
- 恢复后的业务语义校验已强制绑定组织 ID，并通过组织作用域路由核对目录、节点、披露、固定检查点正文和有界审计样本；跨组织复用期望文件会在联网前拒绝。
- PostgreSQL SaaS 停服备份工具已把权威 schema、admission SQLite、alert-outbox SQLite 和精确清单组成原子备份集合，并提供离线哈希、SQLite 完整性和 PostgreSQL archive 目录验证。清单 v2 以固定列、固定类型、主键分页和规范编码保存两张 schema v3 计费表的稳定行数与摘要；离线校验要求 archive 对每张计费表各含且仅含一条结构和数据项，隔离恢复后还可在停服锁表和只读一致快照内重算摘要并失败关闭。清单未签名，只用于发现损坏、漏表和误恢复。专用 `registry_backup` 账号固定为目标库／目标 schema 只读且可绕过强制 RLS，跨库、跨 schema、写入、角色继承和全局默认权限均失败关闭；生产因此要求专用 PostgreSQL 集群。租户 RLS 策略指纹由固定搜索路径下的规范 SQL 表达式、策略结构和角色名生成，不持久化集群局部对象 OID；旧备份恢复后须先用离线迁移账号重算指纹，在线只读校验仍会拒绝任何策略语义篡改。恢复只允许进入新的隔离集群，并须重新固化权限后逐组织做语义比对。
- 本机 PostgreSQL 18 已用真实 SaaS 数据完成一次停服备份和全新容器隔离恢复：当时的 11 张权威表行数与内容摘要一致，覆盖 2 个组织、3 个账号和 29 条领域记录；恢复库在权限重新固化前后均由受限 `registry_app` 通过只读 schema 校验并以 `standard + saas` 就绪，错误日志为空。schema v3 新增的两张计费表已进入备份清单、权限、策略、archive 目录和恢复后摘要比对门禁，但仍须随真实支付数据重跑隔离恢复。两份 SQLite 在本次本地栈中使用带标记的演练库并验证复制后 SHA-256 一致；这不替代生产 admission/outbox 实际文件、异机介质和逐组织登录态语义验收。
- 本地 Keycloak、Registry 和 PostgreSQL 已跑通真实登录、创建组织、切换组织及桌面／移动端页面验证。

### 3. 用户与权限

- 账号：身份服务中的自然人主体，可属于多个组织。
- Owner：管理组织目录、Owner/Admin/Member 角色、团队、节点和组织结账。
- Admin：管理普通成员、团队和节点，不能授予 Owner/Admin，也不能操作组织结账。
- Member：查看本人获授权的披露，绑定本人 DSH，执行获授权的导入和纯文本提问。
- 组织成员身份由 SaaS 控制面确认，组织内细粒度角色与团队权限由该组织的 Registry 目录确认，两层均通过才允许业务访问。
- 角色不自动授予对话正文权限；正文仍须命中成员或团队披露授权。
- 成员暂停、移除、团队变更、披露撤回或到期后，新读取、导入和提问必须失败关闭。

OIDC 账号只证明用户身份，不能代替组织权限、设备密钥、披露数据密钥或 Harness 凭据。旧单组织数据的 Owner 只能通过部署者显式配置的不可变 OIDC 主体认领，不能按显示名称自动认领。

### 4. 核心流程

1. 用户在身份服务注册或登录，Registry 将不可变的 Issuer 与 Subject 映射为全局账号。
2. 没有组织的用户创建组织并成为 Owner；已有组织的用户从组织切换器进入本人有权访问的组织。
3. Owner/Admin 在“成员”页创建一次性邀请；用户登录后接受加入。Owner/Admin 再维护角色和团队，目录写入使用版本号防止并发覆盖。
4. 用户在“DSH 节点”发起绑定；Harness 用 Ed25519 私钥、相互独立的 WSS／HTTPS secret 和一次性挑战完成确认。
5. Harness 只发布用户明确允许的文本事件和检查点；注册站验证组织、实例、签名、顺序、哈希链、授权和幂等键。
6. 获授权成员读取固定检查点内容，可以导入到本人 DSH 的无工具隔离分支，或向来源 DSH 发送纯文本 Agent 请求。
7. 来源 DSH 离线时请求保持排队，恢复后沿持久状态继续；重复提交不重复执行。
8. Owner/Admin 从“审计”页查看不含正文的敏感操作记录。

### 6. 数据与部署

- 正式环境使用 PostgreSQL。SaaS 控制面保存账号、组织、邀请、成员关系、组织创建幂等记录、计费订单和支付提供方事件；每个组织的控制面与 Registry 领域数据均按租户键隔离。
- 本地 JSON／SQLite 只用于兼容开发或独立单组织模式，不作为多组织 SaaS 的生产隔离方案。
- PostgreSQL 离线迁移账号与在线读写账号必须分离；迁移账号只额外获得完整读取会话统计所需的只读内置角色，在线账号不得继承；迁移连接串不能进入 Registry 服务环境，在线配置必须使用 `schemaMode: validate`。
- PostgreSQL 备份账号与迁移、在线账号必须分离；备份账号凭据只能在停服备份时离线注入，不能进入 Registry 服务环境。生产数据库使用专用集群，一套数据库只承载一个权威 SaaS schema；备份集合必须整体复制到限制访问的异机介质。
- 当前运行模型是单 Registry 进程、单副本；组织运行时按需加载并限制缓存数量。持久导入队列和提问邮箱沿用该模型，没有跨副本抢占或租约；现阶段不支持多副本滚动升级或横向扩容。
- Registry 只监听回环或私网地址，由 Caddy 等反向代理提供公网 HTTPS/WSS；公网 HTTP 80 只返回保留原路径与查询的同域 HTTPS 443 永久跳转，不能代理业务响应；数据库端口不得暴露公网。
- Registry、Harness、身份服务、KMS 和支付提供方是独立信任边界；任何一项未配置都必须显示真实缺项。
- 商户密钥只进入部署秘密管理。支付默认关闭；启用时只允许服务端价格白名单和第三方托管结账，订单成功只由验签 Webhook 确认。

### 7. 安全边界

- 只共享用户消息、助手消息、裁剪后的工具结果摘要和标题；不共享隐藏推理、系统提示、原始工具载荷、环境变量、文件正文或附件。
- 外部上下文按不可信引用数据装配，不获得工具、Shell、文件、网络或来源会话权限。
- 每次读取、导入、派发和回复都重新检查账号、组织成员关系、目录授权版本和固定检查点。
- 修改路径 ID、游标、成员 ID、设备凭据或组织 ID，不能跨组织读取、写入或观察资源是否存在；无成员关系统一按不存在处理。
- 事件与请求必须可幂等重放；签名冲突、序号缺口、哈希不一致和未知协议版本失败关闭。
- 撤回不能召回已经被人工复制、导入或返回的文本，界面不得承诺“全局收回”。
- 审计、告警和支付日志不得保存问题、回复正文、卡号、支付密码或私钥。

### 8. MVP 验收

- 新用户能通过正式 OIDC 注册、登录、自助创建组织并成为 Owner；同一账号可切换多个本人所属组织。
- 新用户能通过一次性邀请加入正确组织；重复、过期、撤销或由其他账号接受的邀请失败，暂停／恢复／移除在控制面和目录两层同步生效。
- 两个互不相关的账号和组织在 API、设备同步和 PostgreSQL 行级安全层均不能互相读取、写入或探测资源。
- Owner/Admin 权限矩阵正确，目录并发修改不会静默覆盖；成员停用后下一请求失效。
- 真实 Harness 能绑定、发布披露、断线重连，并保持同一实例身份。
- 授权成员能读取、导入和提问；刷新或进程重启后能找回同一请求与回复；相同幂等键不重复执行。
- Harness 离线不影响注册站和本地会话；排队请求在恢复后继续。
- 撤回、到期或失权后，新读取和新请求立即失败。
- 公网 HTTP 80 到同域 HTTPS 443 的严格跳转、HTTPS/WSS、备份、隔离恢复、告警和秘密管理完成一次真实部署演练。
- 支付未配置时相关 API 返回 HTTP 501 且无结账能力；启用支付时，客户端不能修改服务端价格，组织级幂等键不能创建重复订单，跳转返回不能冒充支付成功，只有验签 Webhook 能更新订单。

### 9. 本轮不做

跨组织共享、公开链接、匿名访问、附件与多模态、全文／语义检索、批量导出、P2P／联邦、来源远程工具执行、自动权限升级、严格端到端加密、完整财务后台、多副本高可用和多主部署。
