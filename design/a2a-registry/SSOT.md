# A2A 注册站：PRD 与剩余 P

## PRD

### 1. 产品目标

交付独立的 `dsh-a2a-registry`：组织成员登录注册站，绑定自己的 DeepSeek Harness，按当前组织权限查看获授权的 DSH 与披露上下文，把固定检查点导入本人 DSH，或向来源 DSH 发送纯文本 Agent 请求并查看回复。

第一版采用“单组织、单注册站进程”的模块化单体。所有资源仍保留 `organizationId`，以后可以演进为多组织，但当前版本不宣称多租户 SaaS 已完成。

### 2. 用户与权限

- Owner：管理组织目录、Owner/Admin/Member 角色、团队、节点和组织结账。
- Admin：管理普通成员、团队和节点，不能授予 Owner/Admin，也不能操作组织结账。
- Member：查看本人获授权的披露，绑定本人 DSH，执行获授权的导入和文本提问。
- 角色不自动授予对话正文权限；正文仍须命中成员或团队披露授权。
- 成员暂停、移除、团队变更、披露撤回或到期后，新读取、导入和提问必须失败关闭。

生产登录使用 OIDC Authorization Code + PKCE。账号只证明组织成员身份，不能代替设备密钥、披露数据密钥或 Harness 凭据。未配置身份服务时保持未配置状态，不提供假登录。

### 3. 核心流程

1. 部署者配置组织、初始 Owner、正式 OIDC 和 HTTPS 域名。
2. Owner 登录，在“成员”页维护角色和团队；写入使用目录版本防止并发覆盖。
3. 用户在“DSH 节点”发起绑定；Harness 用独立设备密钥和一次性挑战完成确认。
4. Harness 只发布用户明确允许的文本事件和检查点；注册站验证组织、实例、签名、顺序、哈希链、授权和幂等键。
5. 获授权成员在“披露”页查看固定检查点内容，可以导入到本人 DSH 的无工具隔离分支。
6. 获授权成员可以发送纯文本问题；来源 DSH 离线时请求保持排队，恢复后沿持久状态继续；重复提交不重复执行。
7. Owner/Admin 从“审计”页查看不含正文的敏感操作记录。

### 4. 页面范围

| 一级页面 | 二级页面／弹窗 | 必需操作 |
| --- | --- | --- |
| 登录 | OIDC 回调、退出 | 登录、退出；未配置时说明原因 |
| 概览 | 运行配置状态 | 查看身份、存储、设备绑定、审计、限流、清理和支付接线状态 |
| 成员 | 成员与团队管理 | 添加、改角色、暂停、恢复、移除；创建、更新、删除团队 |
| DSH 节点 | 节点详情、绑定流程 | 搜索、绑定、审批、改名、撤销、查看连接与接收状态 |
| 披露 | 披露详情、正文 | 筛选、分页、读取固定检查点、选择导入目标、发起文本提问 |
| A2A 分支 | 请求详情 | 分页、查看状态与回复、取消仍可取消的请求 |
| 审计 | 审计列表 | 分页查看主体、对象、动作、结果和时间，不展示正文 |
| 设置 | 接入要求、主题、账号会话 | 查看生产缺项、切换主题、退出 |

### 5. 数据与部署

- 本地开发可使用 SQLite；正式 Registry 领域数据可切换 PostgreSQL。准入限流和告警 outbox 目前仍是各自独立 SQLite owner。
- PostgreSQL 使用非超级用户、受限 schema、小连接池、参数化查询和显式迁移；不能把当前单组织应用隔离宣传为数据库 RLS 多租户。
- Registry 只监听回环地址，由 Caddy 等反向代理提供公网 HTTPS/WSS；数据库端口不暴露公网。
- 商户密钥只进入部署秘密管理。支付默认关闭；启用时只允许服务端价格白名单和第三方托管结账，订单成功只由验签 Webhook 确认。
- Registry、Harness、身份服务、KMS 和支付 provider 是独立信任边界；任何一项未配置都必须显示真实缺项。

### 6. 安全边界

- V1 只共享用户消息、助手消息、裁剪后的工具结果摘要和标题；不共享隐藏推理、系统提示、原始工具载荷、环境变量、文件正文或附件。
- 外部上下文按不可信引用数据装配，不获得工具、Shell、文件、网络或来源会话权限。
- 每次读取、导入、派发和回复重新检查当前成员、授权版本和固定检查点。
- 事件与请求必须可幂等重放；签名冲突、序号缺口、哈希不一致和未知协议版本失败关闭。
- 撤回不能召回已经被人工复制、导入或返回的文本，界面不得承诺“全局收回”。
- 审计、告警和支付日志不得保存问题、回复正文、卡号、支付密码或私钥。

### 7. MVP 验收

- 正式 OIDC 用户能登录；成员停用后下一请求失效。
- Owner/Admin 权限矩阵正确，目录并发修改不会静默覆盖。
- 真实 Harness 能绑定、发布披露、断线重连，并保持同一实例身份。
- 授权成员能读取、导入和提问；刷新或进程重启后能找回同一请求与回复；相同幂等键不重复执行。
- Harness 离线不影响注册站和本地会话；排队请求在恢复后继续。
- 撤回、到期或失权后，新读取和新请求立即失败。
- 公网 HTTPS/WSS、备份、隔离恢复、告警和秘密管理完成一次真实部署演练。
- 支付未配置时无结账能力；启用支付时，跳转返回不能冒充支付成功，只有验签 Webhook 能更新订单。

### 8. 本轮不做

跨组织共享、公开链接、匿名访问、附件与多模态、全文／语义检索、批量导出、P2P／联邦、来源远程工具执行、自动权限升级、严格端到端加密、完整财务后台和高可用多主部署。

| --- | --- | --- | --- |
